# Catalyst rendered-content comparison: build-time candidate

## State and authority

This is a bounded, supplied-HTML comparison component, separate from the lifecycle
diagnostic and all live collectors. It is not a publication verifier or a source
truth check. The parser dependency is parse5 8.0.1; the reviewed npm-generated lock
resolves entities 8.1.0. The isolated dependency preflight is recorded in #637,
comment 5715233099, run 35227185721. That receipt certifies its own integrity,
advisory and smoke-test scope, not this implementation's tests or Astro parity.

Until the new tests and actual locked Astro build execute, this implementation is
an unvalidated candidate. Never reuse the 165 lifecycle tests or the 75 Python
design experiments as acceptance of this Node implementation.

No code in the comparator fetches a URL, reads a file, acquires a clock, accepts an
approval flag, generates content, updates a database, dispatches a workflow,
sends email, closes an incident, or enables enforcement. All result paths retain
false sourceAuthenticityVerified, acquisitionVerified, publicationVerified,
publicationAuthorized, incidentClosureAuthorized and enforcementActive flags.

## Reference and evidence meaning

The reference is complete HTML generated by the actual reviewed, pinned Astro
build. The second input is separately obtained complete HTML. Do not substitute
an approximate Markdown renderer, cleaned browser text or a partial excerpt.
The module accepts two strings and a separately constrained canonical URL. It
does not certify where either string came from or whether a response was complete.

The scheme `usdimpact-catalyst-rendered-v1` is separate from the lifecycle
classifier's synthetic `catalyst-projection-v1` convention. No classifier import,
scheme widening or integration belongs to this change.

- `suppliedUtf8Sha256` hashes the UTF-8 encoding of the exact supplied string.
  It is not an original compressed HTTP-wire hash or an authenticity signature.
- `contentSha256` hashes the serialized normalized governed-content projection.
- A source Markdown byte hash is separate and is never equated to an HTML hash.
- `CONTENT_MATCH_NOT_VERIFIED` means the two accepted projections agree, nothing
  more. A valid but different projection produces `CONTENT_MISMATCH`. Invalid,
  ambiguous, incomplete or unsupported inputs produce a HOLD result.

The current renderer does not emit eventKey, event, sourceEditionDate or generatedAt
as dedicated structured fields. They are source/build provenance, not HTML
observations. Do not fill allegedly observed fields from an expected record.
Displayed source URL/publisher pairs do not independently prove every original
sourceIds relationship. The component checks displayed fact links against the
ledger, but does not reconstruct missing source-only identity.

## Included content

The comparison includes the unique head title, description, canonical URL, UTF-8
charset, language and available robots/googlebot/bingbot indexing declarations.
It includes the whole hero, which is outside main, with the headline, summary,
displayed phase, dates and optional preview archive notice.

The complete main region is retained in order: verification status and assets;
verified-fact cards, labels and source-link destinations; transmission cards;
monitoring list; full analysis; ordered source ledger with identifiers, links,
titles, attribution, classification and dates; and the dedicated article
compliance section. The footer cannot replace that compliance section.

Coverage guards require exactly one hero and one main, the established direct
body placement and main-region ordering, and the current bounded card/list
cardinalities. Displayed phase must match the canonical path suffix; preview
and outcome status-label restrictions remain. Archive notices belong to previews.
Duplicate IDs, attributes, critical metadata and required regions stop acceptance.

## Normalization and rejected input

parse5 supplies HTML5 parsing, entity decoding, source locations and error
reporting. Parsing errors stop acceptance. Governed element start/end tags must
be explicit, with a limited void-element exception. Implicit table sections or
other repaired governed structures are not silently adopted. Unsupported actual
Astro output must be investigated; do not skip it or rewrite articles to pass.

Only ordinary ASCII collapsible whitespace is normalized. Inline boundaries,
Unicode distinctions, non-breaking spaces, punctuation, ordering and code/pre
spacing are retained. Adjacent text across comments is joined without inventing
a word boundary. Whitespace between block elements is not article wording.
Attribute order, class-token order and equivalent character-reference spelling
may normalize. Empty compiler `data-astro-cid-*` markers are excluded; nonempty
or unknown data attributes are not automatically ignored. Other supported
attributes and element semantics remain part of the projection.

Link destinations are parsed as HTTPS URLs, retaining query and fragment
semantics. Relative links resolve against the canonical page. URL credentials,
non-HTTPS schemes, unexpected ports, whitespace and backslashes are rejected.
Canonical URLs use the exact public www origin and a Catalyst preview/outcome
path, without a query, fragment or trailing slash.

Hidden/inert/aria-hidden or inline-styled governed regions and ancestors are held.
Script, style, template, noscript, embedded content, foreign namespaces, event
handlers and unknown governed attributes/elements cannot supply article evidence.
Comments do not substitute for required nodes. Header, footer and outside script
text are not projected. This is NOT CSS visibility, browser behavior, accessibility
or whole-page security certification. In particular, external CSS or scripts can
change what a browser displays without changing the governed static HTML.

Inputs are bounded to 2 MiB of UTF-8, 50,000 traversed nodes and depth 128. Results
are deeply frozen. Unsupported controls and malformed Unicode are rejected. A
safe failure code is returned instead of arbitrary exception text or input echo.
The bounded child-process timeout is an additional limit, not proof that all
possible resource-exhaustion inputs are impossible.

## Local generated-output verifier

`verify-catalyst-rendered-projection.mjs` reads only local files under
`dist/news/catalysts`. It rejects missing/empty inventories, unexpected output
shapes, symbolic links, invalid UTF-8, nonregular files and read-time file changes.
The limits are 256 pages, 2 MiB per page and 16 MiB in total. No source files are
rewritten, no output manifest is written into the public site, and no network
request is made.

Every discovered page must have a valid projection and a deterministic
self-comparison. This verifies supported generated structure, not independent
source-to-page equality. Its result explicitly keeps
`expectedPublicationInventoryVerified`, `independentContentComparisonPerformed`,
`liveAcquisitionPerformed` and `publicationAuthorized` false. Enumerating existing
generated files cannot prove that an expected publication was not omitted.

A future trusted collector must separately establish source/build identity,
complete expected-publication inventory, exact review quality, canonical serving
deployment, complete anonymous acquisition, freshness, current source continuity
and an independently acquired second document. Later deployment ancestry and
content continuity remain separate. Equal start/end repository reads do not
exclude an away-and-back revision change between observations.

## Tests and post-build hook

The offline test file uses synthetic renderer-shaped fixtures and temporary local
output directories. It disables fetch within its own child process. It covers
metadata, hero content, facts, link-only changes, Unicode and inline boundaries,
ordering, code whitespace, archive notices, missing and duplicate regions,
unsafe/unsupported inputs, bounded parsing, non-authorizing results and local
file-safety failures. Synthetic tests are not live HTML captures.

The existing production-build verifier gains two appended `execFileSync` calls,
each with `shell:false`, inherited output and a 30-second timeout: first the
isolated test suite, then inspection of actual generated Catalyst output. Existing
checks remain unchanged. A missing file/dependency, test failure, signal, timeout
or generated-output HOLD fails the build. Do not disable or skip a failing page.

Acceptance requires successor-head Web Quality (including these new checks),
Dependency Review, CodeQL, and a matching READY Preview. An older green head is
insufficient. No main merge, Production activation, renderer/schema/article edit,
workflow definition, new permission or live-monitor integration is authorized by
this candidate. #615, #631 and its existing read-only watch remain separate.


## Additional local hardening review (September 17, 2026)

The candidate now rejects any HTML `base` element rather than resolving all relative
links against an assumed canonical base. It also rejects a refresh directive in a
meta element. These document-level inputs must not be ignored in article comparisons.
After parsing, every text-node value and attribute value is screened for the same
unsupported control characters as the supplied HTML, so numeric character references
cannot bypass raw-input screening. Content Security Policy meta elements are not
classified as refresh directives.

Thirteen additional full-parser regression scenarios are written in the normal test
suite. They remain unexecuted until the genuine pinned parse5 dependency is available.
A separate, explicitly limited helper-level test executes exact extracted candidate
functions against synthetic already-decoded nodes; it is not HTML parser execution,
Astro-output validation, CI acceptance or publication proof. The repository branch is
not changed by this local review.
