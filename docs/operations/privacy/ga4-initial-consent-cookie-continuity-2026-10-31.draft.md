# GA4 deferred-consent initialization continuity — Draft-only remediation (2026-10-31)

**Finding:** An external owner-supplied read-only QA report reviewed USD Impact privacy source at Production main `743872f3fdfd5fdddd242b64e7a42674a459a416`. It inferred that `GoogleAnalyticsClient.astro` uses an inline `define:vars` script that calls `applyConsent()` before Astro's processed `ConsentClient.astro` module installs `window.USDImpactConsent`. On returning already-granted sessions, this can execute `disableGa4()` and attempt to expire `_ga` cookies on every full-page navigation. **This is inferred from script ordering; there is no independent actual Production cookie continuity trace.** No data leak is alleged.

**Narrow code change:** If the consent API already exists, call `applyConsent()` as before. If not, set the Google `ga-disable` flag to true while waiting for the existing `usd-impact:consent-ready` event, without deleting any pre-existing cookies or constructing Google APIs. The already-present event listener applies the verified consent when `ConsentClient` is initialized. Explicit rejection/withdrawal still expires accessible GA cookies, updates consent to denied after prior opt-in, and prevents post-rejection events.

**Regression:** Extend the disconnected Node VM lifecycle test to emulate two separate page loads with delayed consent API and a stable prior `_ga` identifier. Verify consent-ready initializes exactly one tag per document, granted cookies survive, withdrawal sends denied update and deletes cookies, and first-time denied consent cleans stale GA cookies without loading Google. This does **not** replace actual same-origin browser `_ga` continuity QA. No real Google requests, user IDs, cookie values or deployment required.

**Change scope:** GoogleAnalyticsClient.astro, its dedicated disconnected test, and this Draft evidence note only. No change to ConsentClient, TelemetryClient, public notices, operator terms, original Score, Macro Weekly article, source-rights or commerce. All PR changes are **Draft HOLD** until exact-head CI, scope review, owner Preview QA, and an independently authorized Production merge. The previously completed privacy PR #1035 remains historically correct for the withdrawal hardening it actually shipped.

**References:** [Astro client script processing](https://docs.astro.build/en/guides/client-side-scripts/), [Astro define:vars semantics](https://docs.astro.build/en/reference/directives-reference/#definevars), [GitHub Macro Weekly #1025](https://github.com/usdimpact/usd-impact-site/pull/1025).

**Stop rules:** If simulated return consent/first-time rejection breaks, fail CI; do not silently enable advanced consent mode, ads, cookies before permission, new trackers or Vercel Preview/Production. A separate exact-SHA Production approval is required even if all CI is green.
