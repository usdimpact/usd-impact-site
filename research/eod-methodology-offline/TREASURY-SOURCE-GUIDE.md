## Why this source first

Treasury publishes a government-originated daily par yield-curve XML feed. Its official documentation specifies the month query, the native observation date and the tenor fields. This adapter accepts **only** the exact official monthly yield-curve endpoint for the New York business-day under consideration:

- Guide: https://home.treasury.gov/treasury-daily-interest-rate-xml-feed
- Canonical endpoint: https://home.treasury.gov/resource-center/data-chart-center/interest-rates/pages/xml?data=daily_treasury_yield_curve&field_tdr_date_value_month=YYYYMM
- Fields: `NEW_DATE`, `BC_2YEAR`, `BC_10YEAR`.
- Source units: two-year and ten-year **yields are percentages**; their arithmetic difference is in **percentage points**. The validated record and EN/ES renderers preserve that distinction.
- Month binding: a monthly response with any out-of-month observation is rejected rather than treated as a quiet-day or valid publisher update.
- Calculation: the directly reproducible **Treasury 10-year minus 2-year par-yield spread**, in percentage points. This is **not** the original Score v2 Treasury DGS2/DGS10 vendor transport, nor the eight-factor Score, nor a trading instruction.

Treasury's government publisher status reduces source ambiguity. It **does not automatically certify** the contractual and legal public use of every input quotation, downstream derived display, or the original USD Impact Score. Original third-party licensing remains on HOLD. Any future published numeric series requires its own source-rights and editorial approval.

## Interface and control boundaries

The `verified-treasury-source.mjs` adapter:

1. Builds a fixed HTTPS Treasury monthly feed URL from a validated `YYYY-MM-DD` date. Rejects redirects, wrong issuer URLs, non-XML responses, HTTP failures and oversized bodies.
2. Requires **18:30 or later in America/New_York** on the matching business-day in default mode. Treasury's official methodology states the day's par yields are *usually available by 18:00 Eastern, but may be delayed*; 18:30 is only a conservative research buffer, **not a guarantee**. Missing current-day observations stay held or become an explicitly dated no-observation educational note, never invented market facts. This source-specific cutoff is deliberately different from the unrelated **17:37 synthetic research dry run** in parent #1082, which remains OFF by default and must never be wired to this real-source adapter without separate schedule authorization.

   **Explicit delayed-source review:** A private opt-in adapter option `allowRetrospective: true` permits a weekday observation to be inspected **1–14 calendar days later**; weekend capture of a Friday observation is allowed. The CLI requires the exact separate `--live-official --probe-date=YYYY-MM-DD --allow-retrospective` flag trio; its ordinary `--live-official` mode remains same-day only. Observation date and later capture time remain separate in English and Spanish, and first publication time stays unverified. The disabled 17:37 research workflow never calls the real adapter. No historic scores or public editions are authorized.
3. Parses a tightly scoped, size-bounded XML subset from the official feed: unique observation dates; exact two- and ten-year par yields; no `DOCTYPE`, dynamic XML entities or unknown numeric fields. Missing rates and duplicates FAIL; a valid feed without the target date yields a labeled `NO_MATCHING_OBSERVATION_DRAFT`.
4. Stores an integrity hash and limited source metadata in the transient candidate object, **not raw vendor data archives**. `feed/updated` is **not** a certified publication time: original issuer release instant is explicitly `null`.
5. Produces one canonical fact list and deterministic EN/ES Markdown drafts with identical IDs, values and source URLs; no text suggests Treasury curves prove a dollar/gold/oil/BTC/equity price move.
6. Returns `public_release_authorized:false`, `human_editorial_review_required:true`, `source_rights_status:SEPARATE_LEGAL_EDITORIAL_REVIEW_REQUIRED` and `original_score_reconstruction_authorized:false` in all cases.
7. Local hand-supplied XML always receives `UNVERIFIED_FIXTURE` provenance, even if a caller tries to pass a stronger transport flag. Only the explicit exact-origin fetch function can label a response `EXACT_ISSUER_RESPONSE`; that label **does not establish rights or original issuer release time**.
8. **Origin attestation cannot be inferred from an injected fetch.** `EXACT_ISSUER_RESPONSE` confirms only that an injected HTTP response reported the pinned URL and passed parser/HTTP format checks; the separate `origin_provenance_level` explicitly states `ASSERTED_EXACT_RESPONSE_URL_NOT_INDEPENDENTLY_ATTESTED`, with `issuer_payload_origin_independently_attested:false`. A fixture cannot upgrade itself to a verified issuer source, rights-cleared status or approved historical vintage. Future integration must independently validate TLS/origin provenance and source terms before calling real values issuer-verified.
9. **Private record invariants fail closed.** Rendering or producing a redacted receipt rejects a forged publication timestamp/verification, licence status, claimed source authentication, changed editorial status, changed edition ID, price-causation/trading claim classification, changed documentation link, or an attempt to bypass the existing News boundary. A fact-bearing candidate must remain `AWAITING_EDITORIAL_REVIEW`; `public_release_authorized:false` remains mandatory.


**Primary publication-timing source:** [Treasury Yield Curve Methodology](https://home.treasury.gov/policy-issues/financing-the-government/interest-rate-statistics/treasury-yield-curve-methodology) explicitly states rates are typically available by **6:00 p.m. ET** and can be delayed. Separately, 3:30 p.m. ET is approximately when indicative *inputs* are collected, not when the resulting public XML has necessarily been published. Never equate those two times or use source `feed/updated` as a verified initial availability timestamp.

**Exact source digest contract (private research only):** On a streamed HTTP response, the adapter hashes the **exact UTF-8 bytes delivered by `fetch` to the XML decoder** and records `source_hash_basis: FETCH_BODY_BYTES_POST_HTTP_DECODING`. This is the source body as made available after any automatic HTTP content decompression, **not a guaranteed wire-level compressed-byte hash or an attestation of publisher identity**. It refuses malformed UTF-8 and non-binary chunks. Non-streaming injected/mock `response.text()` fallbacks are explicitly labelled `REENCODED_TEXT_FALLBACK_NOT_RAW`, while local fake fixtures are `UTF8_FIXTURE_TEXT`; neither fallback is a certified raw-source receipt. No raw numeric payload is included in CLI output or committed to GitHub. Hashes support source-content comparison, not copyright clearance, first-publication timing, or the original licensed Score.

**HTTP header evidence contract:** The privately invoked source adapter validates successful HTTP 200 and an XML MIME type and now reports the normalized MIME category plus boolean presence of HTTP `Date`, `Last-Modified` and `ETag`. The actual header timestamp/body strings are deliberately not reproduced in CLI output. In particular, `Last-Modified` or Atom `updated` **must never be presented as the first release timestamp** without issuer-specific provenance evidence. An absent header is reported as absent, not inferred. This header contract is now **executed against one real Treasury response** by the exact Node adapter: HTTP 200 and `text/xml`, `Date` present, `Last-Modified` and `ETag` absent; see the one-shot receipt above. The full-source parser gate passed for October 30 only. First issuer publication/revisions, source reuse and scheduled/public release remain HOLD.

**Official XML compatibility change:** Treasury's [developer notice](https://home.treasury.gov/developer-notice-xml-changes) says the post-February-2022 feed omits elements when their values are unavailable, rather than necessarily emitting old `m:null="true"` elements. This adapter treats both a missing 2Y/10Y field and an empty field as **missing data, never zero**, and it ignores unrelated additional tenor elements such as the documented 2025 1.5-month series. `NEW_DATE` requires a complete lexically valid OData date-time; Treasury's [XML feed reference](https://home.treasury.gov/treasury-daily-interest-rate-xml-feed) describes `Edm.DateTime` as allowing `yyyy-mm-ddThh:mm` with optional seconds (and optional fractional seconds). The adapter accepts those documented forms while rejecting arbitrary suffixes and invalid clock values. The specialized malformed/omitted-field cases remain fixture-tested; separately, the exact Node parser successfully handled the **real October 30 fetched XML body** in one controlled read-only GitHub job. That sample does not certify every malformed-field or historical-month case. The notice's 2022 restriction on browser access describes the *all-period XML view*, not necessarily all monthly API requests.
